# 视觉挥杆触发与手动录像设计

## 背景与已确认目标

自动练习当前通过麦克风音量峰值判断击球。这个触发方式与产品目标不一致，也会漏掉空挥、软击，并受到环境噪声影响。自动练习应当观察画面中的人物和挥杆动作，不依赖击球声。

真机排查还确认了一个独立问题：自动练习生成的视频文件本身完整可播放，样本为 3 秒、1280×720、约 239.9 FPS，但 P1–P8 分析器使用零时间容差请求源帧。高帧率文件的标称帧率和实际帧时间存在微小差异，导致 `AVAssetImageGenerator` 无法精确命中请求时间，最终报告 `frameExtractionFailed`，界面却显示误导性的“请重新导入”。

本设计同时完成以下目标：

- 自动练习改为人物姿态和挥杆动作触发，不使用麦克风检测。
- 空挥、软击和环境噪声下仍能自动生成挥杆视频。
- 首页增加独立的手动录像入口，不依赖任何视觉识别。
- 手动录像点击后立即开始，再次点击停止，15 秒时自动停止。
- 自动与手动录像共用同一套持久化、媒体校验和分析交接流程。
- 修复 239.9/240 FPS 视频的精确抽帧失败，同时保留唯一源帧校验。

## 范围与非目标

本次范围包括自动练习触发、手动录像入口、捕获视频持久化、媒体校验、高帧率抽帧兼容和相关界面状态。

本次不重新设计 P1–P8 求解器、不改变绘图和回放工具、不增加云端处理，也不使用杆头或球的实时目标检测。实时触发只使用人物姿态；完整 P1–P8 分析仍在视频保存后执行。

## 产品行为

### 自动练习

用户选择 DTL 或 FACE-ON、确认机位并点击“开始自动练习”后，界面依次呈现：

1. `正在寻找人物`
2. `人物已入镜，请准备`
3. `检测挥杆中`
4. `正在生成视频`

只要人物稳定入镜，系统就持续观察肩、肘、腕和髋部的归一化运动。单纯站立、走动、弯腰或调整球位不能生成视频。检测到连续挥杆动作后，系统保存起杆前 1.0 秒到收杆后 0.8 秒的片段。

如果已经可靠检测到起杆，但 5.0 秒内没有检测到收杆，系统保留该片段并将捕获质量标记为“可能不完整”，而不是静默丢失。后续分析可以返回 `incompleteSwingClip`，但原视频始终可在项目中查看。

自动练习不创建或消费麦克风音量样本，也不以击球声作为辅助触发。自动练习视频不依赖麦克风权限。

### 手动录像

首页新增独立的“手动录像”卡片。进入后：

- 点击录制按钮立即开始，没有倒计时。
- 再次点击停止。
- 用户未停止时，录制到 15 秒自动结束。
- 手动模式不运行人物稳定或挥杆动作检测。
- 保存并校验成功后直接进入与导入视频、自动练习相同的分析工作区。

## 架构

### 1. 相机与实时取样

`CameraStateModel` 继续拥有唯一的 `AVCaptureSession`、录像输出和串行 `sessionQueue`。自动练习在同一会话中增加 `AVCaptureVideoDataOutput`，并设置 `alwaysDiscardsLateVideoFrames = true`。输出仍可维持设备支持的高帧率录像，但视觉支路最多每秒接收 12 个待分析帧；其余帧在进入 Vision 前丢弃。

视觉委托在独立 `visionQueue` 上运行，不阻塞会话配置、录像开始/停止或主线程。若设备无法同时提供高帧率录像与视频数据输出，配置依次降级到 120 FPS、60 FPS；不得退回声音触发。所有降级都需要在状态中可观察，并由真机测试确认最终帧率。

### 2. 轻量人物姿态取样

新增 `LivePoseSampler`，只负责把低频视频帧转换成触发器需要的最小姿态样本：

- 相机展示时间戳；
- 肩、肘、腕和髋部关键点及置信度；
- 身体中心、肩宽或躯干长度；
- 以身体尺寸归一化的关节速度。

它不复用完整视频 P1–P8 分析器，也不做杆身、球位、关键帧或技术动作评价。实时路径保持轻量、可丢帧且有明确延迟上限。

### 3. 视觉挥杆状态机

新增纯策略组件 `LiveSwingTriggerDetector`。输入是按时间排序的姿态样本，输出是状态变化和捕获边界。状态为：

- `searchingForPerson`：关键躯干关节不足，或人物尚未稳定。
- `ready`：同一人物连续至少 0.5 秒稳定可见。
- `swingInProgress`：腕部相对躯干的运动持续多个样本，并与肩/髋协调运动共同超过起杆阈值。
- `finishing`：动作经过方向变化并进入击球后延伸区域。
- `completed`：人物运动在有效挥杆持续时间后明显减速，确认收杆。
- `cooldown`：阻止同一次动作重复触发，直到人物重新稳定。

阈值均使用身体尺度和时间归一化，不使用固定像素距离。DTL 和 FACE-ON 可以使用各自配置，但共享同一个状态机接口。视觉状态机不要求检测到球、杆或击球声，因此空挥也能完成。

默认触发配置为：12 FPS 视觉取样、0.5 秒人物稳定确认、连续 3 个样本确认起杆、0.7 秒最短有效挥杆、5.0 秒最长挥杆、0.35 秒低运动确认收杆，以及 0.75 秒触发冷却。腕部速度、肩髋协同和低运动阈值以躯干长度每秒为单位，并集中在 `LiveSwingTriggerConfiguration` 中；初始数值必须由固定 DTL、FACE-ON、空挥和非挥杆样本测试锁定，不能散落在界面或相机代码中。

起杆后超过 5.0 秒仍未完成时，状态机输出 `possibleIncomplete`，并给出已有的开始和截止时间。人物在起杆前消失则回到 `searchingForPerson`，不生成空片段。

### 4. 录像时间轴与截取

用户开始自动练习后，录像输出持续写入临时源文件。视觉样本和录像使用同一捕获时钟；以第一个有效视频样本建立源文件相对时间原点，避免用 `Date` 推断帧位置。

视觉触发器输出：

```swift
struct PracticeCaptureBoundary {
    let swingStartTime: CMTime
    let swingEndTime: CMTime
    let quality: PracticeCaptureQuality
}

enum PracticeCaptureQuality {
    case complete
    case possibleIncomplete
}
```

截取窗口默认从 `swingStartTime - 1.0s` 开始，到 `swingEndTime + 0.8s` 结束，并裁剪到实际源文件范围。视觉完成后等待后置时间，再停止临时源录像并导出目标片段。

### 5. 统一持久化与媒体校验

新增独立的捕获媒体持久化边界 `CapturedVideoStore`。自动和手动路径都把临时文件交给它，而不是直接把 `/tmp` URL 交给工作区。

保存流程为：

1. 复制或导出到应用支持目录中的临时文件名。
2. 异步加载 `AVAsset` 的时长和视频轨。
3. 验证文件存在、大小大于零、时长有限且大于零、至少包含一条可读视频轨。
4. 原子移动为最终 `practice-<UUID>.mp4` 或 `manual-<UUID>.mp4`。
5. 返回持久 URL 和捕获质量，再创建项目并触发分析。

任何一步失败都不得创建空项目，也不得删除仍可恢复的临时源文件。失败信息必须说明是相机、导出、存储空间还是媒体校验问题，并允许重试或返回。

### 6. 239.9/240 FPS 抽帧

完整视频分析器继续按源帧索引规划采样，但 `AVAssetImageGenerator` 不再把 `requestedTimeToleranceBefore` 和 `requestedTimeToleranceAfter` 固定为零。容差使用标称帧率计算的半帧时长。

生成器返回图片后仍必须验证：

- 实际时间有限且有效；
- 实际时间映射到唯一源帧；
- 与请求帧的距离小于半帧；
- 观察到的帧索引等于请求帧索引。

因此修复的是“非整数标称帧率无法精确请求”的解码问题，不放宽 P1–P8 的帧身份约束。媒体读取失败和动作分析失败也必须使用不同文案；已持久化且可播放的视频不得提示用户重新导入。

## 组件与接口变化

- `PracticeHomeAction` 增加 `manualCapture`，首页模式顺序加入“手动录像”。
- `ContentView` 增加手动相机展示和完成回调；成功媒体仍使用 `.capturedClipSaved` 进入工作区。
- `CameraStateModel` 移除自动练习的音频峰值触发职责，增加可选的视频数据输出和视觉帧委托。
- `PracticeClipRecording` 返回包含 URL 和捕获质量的结果，而不是裸 URL。
- `PracticeSessionEngine` 根据视觉触发状态发布远距离可读的界面状态，并把完整/可能不完整质量传给交接层。
- `CapturedVideoStore` 统一自动和手动媒体的持久化与校验。
- `LivePoseSampler` 与 `LiveSwingTriggerDetector` 保持独立，前者依赖 Vision，后者是可用固定样本测试的纯状态机。

## 错误与降级行为

- 相机权限被拒绝：不进入等待状态，提供系统设置入口。
- 视觉视频输出不可用：明确显示“此设备无法启动视觉检测”，提供手动录像入口；不启用声音触发。
- 高帧率和视觉输出不能共存：降级帧率并继续视觉触发，同时记录最终捕获帧率。
- 人物在起杆前离开：回到寻找人物，不保存。
- 起杆后人物丢失或未完成收杆：保存 `possibleIncomplete` 片段。
- 导出失败：保留临时源文件并允许重试。
- 存储空间或原子移动失败：不创建项目，显示可执行原因。
- 媒体有效但 P1–P8 失败：保留项目和视频，显示具体分析失败，不提示重新导入。
- 用户离开页面：取消 Vision 工作、停止录像并清理没有恢复价值的空临时文件。

## 测试策略

### 单元测试

- 人物缺失、人物稳定和人物重新进入的状态转换。
- 站立、走动、弯腰和调整球位不触发。
- DTL、FACE-ON、空挥和软击姿态序列可触发一次完整挥杆。
- 起杆后丢失人物或超时输出 `possibleIncomplete`。
- 冷却状态防止一次挥杆重复保存。
- 手动录像点击立即开始、再次点击停止、15 秒自动停止。
- 自动与手动媒体都经过同一持久化和校验接口。
- 239.9、240、120、60、59.94 和 30 FPS 的半帧容差与源帧映射。
- 文件缺失、零字节、零时长、无视频轨、复制失败和移动失败。

### 集成测试

- 固定姿态样本驱动视觉状态机，验证捕获窗口含起杆前 1.0 秒和收杆后 0.8 秒。
- 使用本次真机 239.9 FPS 样本验证首帧、末帧和中间帧可解码，且实际帧索引与请求一致。
- 自动和手动生成的视频都先进入应用支持目录，再创建本地项目并自动分析。
- 重新打开历史项目不重复触发自动分析。
- 取消、页面退出和失败重试不会留下活跃会话或重复回调。

### 真机验收

在无线连接的实际 iPhone 上分别验证 DTL 和 FACE-ON：

- 人物走入、站稳、走出和重新进入。
- 正常挥杆、空挥、轻击、环境噪声和没有击球声。
- 站立、试握杆、弯腰放球和走动不会误生成视频。
- 自动片段包含完整起杆前后动作，保存后可播放并能进入 P1–P8 分析。
- 手动录像点击即录、手动停止和 15 秒自动停止均有效。
- App 不请求或使用麦克风进行自动检测。
- 最终视频实际帧率与降级状态可见，239.9/240 FPS 视频不再出现“视频读取失败，请重新导入”。

## 完成标准

只有当自动练习完全由画面人物挥杆触发、手动录像入口可用、两条路径均持久化并校验媒体、高帧率样本能通过抽帧进入分析，并在真机完成上述验收后，本工作才算完成。
