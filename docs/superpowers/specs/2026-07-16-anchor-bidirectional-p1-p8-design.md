# SwingArc 锚点与双向搜索 P1–P8 设计

**日期：** 2026-07-16

**状态：** 方案 B 已确认，待规格评审

**验收精度：** P1–P8 均须落在人工标准帧的正负 1 个源视频帧内

## 目标

把现有“粗扫截取固定窗口，再让八个阶段独立竞争帧”的主流程，改为“定位挥杆高速核心、建立击球候选锚点、向前搜索 P5 至 P1、向后搜索 P7 至 P8、最后执行全局约束求解”。

自动结果必须引用真实源视频帧。证据不足时返回低置信度或未确定，不允许为了凑齐 P1–P8 而选择不符合阶段定义的帧。

本规格取代以下旧约定：

- `SwingWindowLocator` 的输出不再直接作为最终精扫窗口；
- 不再依赖固定 `1.5s` 前置缓冲和 `1.0s` 后置缓冲覆盖完整挥杆；
- 不再接受“P6 正负 1 帧、其余阶段正负 2 帧”的旧精度目标；
- 单帧阶段高分不能单独决定 P1、P4 或 P6。

旧规格中的本地分析、真实源帧、人工锁定优先、严格时序、可取消任务和不伪造结果等要求继续有效。

## 已确认的失败证据

基准视频 `/Users/liangbo/Desktop/IMG_4500.mov` 为 30 FPS、25.23 秒。

当前主流程输出的精扫窗口为 `13.733s–19.367s`。逐帧检查显示：

- 真正准备位和起杆开始早于 `13.733s`，因此 P1 和 P2 在进入阶段求解器之前已经被裁掉；
- 当前 P1 `13.767s` 已进入起杆，不能代表准备位；
- 当前 P4 `14.833s` 位于顶点停顿平台前缘；双手到约 `15.10s` 才结束平台并开始持续下杆；
- 当前 P6 `16.000s` 接近击球，但球仍可见，击球发生在随后约一个源帧内；
- P3、P5、P7 和 P8 已落在视觉正确阶段附近，说明人体追踪和大部分几何特征可继续使用。

对应根因是窗口边界、阶段转移和缺失证据处理，而不是 Apple Vision 在关键帧没有输出人体。

## 范围

### 本次包含

- 正面或近正面、固定机位、单次完整挥杆；
- 左右手球员，但前导臂在单次分析内必须固定；
- 慢起杆、顶点短暂停顿、击球运动模糊和收杆后继续走动；
- 30–120 FPS 源视频；低帧率视频不插帧；
- 人体姿态、双手相对髋部位置、前导臂、肩髋轴、杆身和球位的联合判定；
- 人工标记继续作为最高优先级，不被重新分析覆盖。

### 本次不包含

- 挥杆优劣评分、动作问题诊断或教学建议；
- 任意机位、多人同时挥杆或移动镜头；
- 在线模型服务；
- 训练新的时序机器学习模型。

## 总体数据流

```text
完整视频
  → 8 FPS 姿态粗扫
  → 高速挥杆核心与主球员轨迹
  → 自适应源帧精扫
  → 击球候选走廊
  → 对每个击球候选执行向前/向后阶段搜索
  → 全局约束选择最优完整路径
  → P1–P8 时间、帧号、置信度和证据说明
```

粗扫只回答“挥杆高速核心在哪里”，不再声称已经找到 P1 和 P8 的完整边界。

## 组件设计

### 1. `SwingCoreLocator`

以当前约 8 FPS 的人体姿态粗扫全片，继续使用经过平滑的双手运动、肩轴和髋轴能量，并保留主球员跨帧追踪。

输出内容：

- 唯一主球员轨迹；
- 一个或多个高速核心候选；
- 核心峰值时间和粗略方向；
- 人体覆盖率和候选歧义状态。

它不再添加固定前后缓冲，也不再因为包含完整慢起杆后超过 6 秒而直接拒绝。若存在两个强度接近的独立挥杆核心，仍返回候选歧义。

### 2. `AdaptiveSwingSampler`

围绕高速核心先建立一个小型初始精扫区间，并按源视频帧率读取姿态。随后根据阶段边界证据自适应扩展：

- 向前扩展，直到找到“稳定准备平台 + 随后的持续起杆”；
- 向后扩展，直到找到“P7 后第一个稳定收杆平台”；
- 每次扩展使用固定的小时间块，避免重复扫描已读取帧；
- 到达视频边界、最大分析跨度或任务取消时立即停止。

最大分析跨度设为 8 秒，只作为异常保护，不作为阶段边界。若 8 秒内仍找不到合法 P1 或 P8，返回明确的边界缺失状态，而不是截断后继续硬解。

精扫姿态覆盖全部自适应窗口；耗时较高的杆身和球位轮廓检测仍只在阶段候选附近稀疏执行。

### 3. `SwingEvidenceTimeline`

把每个源帧转换为按时间排序的统一证据，并保留原始帧号。现有五帧中值姿态平滑和肩髋无方向轴处理继续使用。

除现有特征外，新增以下短窗口特征：

- 双手速度方向连续性，而不是只看单帧速度；
- 双手高度平台的起点、终点和持续时间；
- 上杆、下杆和送杆的持续方向投票；
- P1 前后的稳定到运动转移；
- 杆身候选的跨帧角度连续性；
- 球位候选的稳定度和击球前后局部变化；
- 关节缺失和 Vision 左右标签交换的质量标记。

所有窗口判断都使用时间长度，并换算到实际源帧，不能假设固定 30 FPS。

### 4. `ImpactCorridorResolver`

击球不是先验确定的单帧，而是一个短候选走廊。候选由以下证据共同生成：

- 双手位于髋部或前侧大腿附近；
- 双手速度和加速度处于下杆局部高位；
- 髋部已经打开，肩髋转动方向与下杆一致；
- 杆身延长线接近稳定球位；
- 球位附近出现局部变化或球消失；
- 候选必须晚于上杆顶点并早于持续送杆。

杆球证据完整时可生成高置信度 P6 候选。杆球证据缺失时仍保留人体候选，但最多为低置信度，并让多个候选进入后续全局求解，不能过早锁死一个手髋邻近帧。

### 5. `BidirectionalStageCandidateResolver`

对每个 P6 候选分别生成阶段候选集。

#### 向前搜索：P5 → P1

- **P5：** P6 前最近一次前导臂接近水平，且双手持续下行、髋部已开始打开；
- **P4：** P5 前的双手最高平台。平台允许短暂近零速度；P4 取“持续下杆开始之前的最后一个平台帧”，不得取平台前缘；
- **P3：** P4 前前导臂接近水平并保持伸展，双手处于上升路径，肩部转动继续增加；
- **P2：** P3 前杆身接近水平、双手仍处于躯干下半区且已经离开准备位；杆身缺失时只能低置信度；
- **P1：** P2 前最后一个稳定准备帧。其后必须出现达到最短持续时间的单向起杆，普通站立静止或挥杆中途短暂停顿不能作为 P1。

#### 向后搜索：P7 → P8

- **P7：** P6 后双手持续上升，前导臂或杆身进入送杆平行区，胸髋继续朝目标方向转动；
- **P8：** P7 后第一个稳定收杆平台，允许极少量单帧姿态噪声；后续走动和片尾静止不能替换它。

每个阶段可保留多个候选以及必需证据是否满足的信息，不在候选生成阶段贪心决定最终帧。

### 6. `ConstrainedSwingPathSolver`

全局求解器从不同 P6 走廊及其双向候选中选择一条完整路径。约束包括：

- 帧号严格满足 `P1 < P2 < … < P8`；
- P1 后必须为持续上杆，P4 后必须为持续下杆，P6 后必须为持续送杆；
- P3/P5 必须位于相反运动方向的前导臂平行位置；
- P4 必须位于顶点平台末端；
- P8 必须是第一个合法稳定平台；
- 阶段间隔使用宽松的生理合理范围，并根据本次挥杆节奏调整，不能用固定视频比例生成阶段。

路径总分由阶段证据、转移证据、缺失证据惩罚和次优路径余量组成。阶段必需证据不满足时，状态必须降级；全局顺序本身不能把弱候选升级为已确认。

## 阶段精确定义

| 阶段 | 自动选择定义 | 已确认所需关键证据 |
| --- | --- | --- |
| P1 | 持续起杆前最后一个稳定准备帧 | 稳定窗口、低位双手、后续持续起杆 |
| P2 | 上杆中杆身最接近水平的真实帧 | 上杆方向、杆身水平、双手仍在下半区 |
| P3 | 上杆中前导臂最接近水平的真实帧 | 前导臂伸展、上杆方向、肩转增加 |
| P4 | 顶点平台末端、持续下杆开始前最后一帧 | 高位平台、随后持续下杆、肩转支持 |
| P5 | 下杆中前导臂最接近水平的真实帧 | 下杆方向、前导臂伸展、髋部打开 |
| P6 | 杆头到达球位的击球帧 | 杆球邻近或球位变化；缺失时不得确认 |
| P7 | 击球后送杆平行区的真实帧 | 上升方向、手臂或杆身平行、胸髋延续 |
| P8 | 第一个持续稳定的收杆平台起始帧 | 短窗多数稳定、位于 P7 后、排除走动 |

## 置信度与错误处理

### 状态

- `confirmed`：阶段必需证据满足，且最优候选相对次优候选有足够余量；
- `lowConfidence`：帧真实、顺序合法，但杆球、前导臂或姿态覆盖等关键证据缺失；
- `unresolved`：找不到符合阶段定义的候选，不返回时间和帧号。

### 明确失败原因

分析层应能区分：

- 找不到稳定主球员；
- 存在多个同等挥杆核心；
- 找不到 P1 的准备到起杆边界；
- 找不到 P4 的平台到下杆转移；
- 找不到可信击球走廊；
- 找不到 P8 的稳定收杆；
- 视频缺少挥杆前段或后段；
- 分析被取消或帧读取失败。

不得把上述失败统一显示成“识别数量不足”，也不得用固定时间点补齐。

## 性能设计

- 粗扫保持约 8 FPS，只执行人体姿态；
- 自适应精扫只读取尚未缓存的源帧；
- 姿态证据覆盖完整自适应窗口；
- 杆身和球位检测只在 P1、P2、P6、P7 候选邻域运行，并保持总帧数上限；
- 25 秒、30 FPS 基准视频目标仍为 45 秒内完成；
- 分析进度按粗扫、边界扩展、候选证据和全局求解真实计算；
- 新分析启动或用户取消后，旧任务不得回写结果。

## 测试与验收

### 1. 人工标准帧

在修改规则前，对每段验收视频执行两次独立逐帧标注并冻结源帧号。两次标注不一致时，以逐帧回放复核后确定唯一标准帧。测试代码只读取冻结标注，不根据当前算法输出反向修改标准答案。

基准视频必须覆盖已确认的三个失败模式：慢起杆导致 P1/P2 被裁掉、P4 存在停顿平台、P6 球位证据不稳定。

### 2. 纯逻辑回归

- 慢起杆能触发向前扩展并找到准备位；
- 没有准备位的视频返回缺少前段，不伪造 P1；
- 顶点停顿平台选择末端，而不是第一个高位帧；
- P4 后出现至少一个短噪声帧时仍要求持续下杆；
- P3/P5 使用相反运动方向区分；
- 多个手髋邻近帧由杆球和全局路径选择 P6；
- 球位缺失时 P6 不得为已确认；
- 收杆中单帧抖动不推迟 P8，后续走动不替换 P8；
- Vision 左右标签交换不产生 180 度假旋转；
- 不同帧率使用同一时间窗口语义且只返回真实源帧。

### 3. 真实视频验收

每段视频输出以下报告：

- P1–P8 人工帧、自动帧和绝对帧误差；
- 阶段状态和置信度；
- 人体、前导臂、杆身和球位证据是否存在；
- 自适应窗口边界和分析耗时；
- 未通过阶段的主要失败原因。

对具备完整挥杆前后段、固定机位和足够人体覆盖的验收视频，P1–P8 每个阶段都必须在人工标准帧正负 1 个源视频帧内。任何阶段超出范围即判定该视频未通过。

跨视频验收至少包含 5 段同类视频，并覆盖不同球员、快慢节奏、30/60/120 FPS 和不同背景。存在严重遮挡或视频本身缺段的样本用于验证降级行为，不纳入“必须自动确认八阶段”的合格样本集合。

## 交付边界

本设计只重构 P1–P8 的窗口、候选和时序求解逻辑，不改变分析工作台、画线工具、项目存储格式或人工阶段调整交互。

实现应尽量保留现有 `SwingFrameSample`、`SwingFrameEvidence`、`SwingAnalysisResult` 和 UI 数据接口，避免影响已经完成的 iPhone/iPad 界面。
