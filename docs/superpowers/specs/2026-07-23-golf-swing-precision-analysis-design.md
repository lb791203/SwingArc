# SwingArc 高精度挥杆识别与参数分析设计

**日期：** 2026-07-23

**状态：** 整体设计已确认，待实施计划

**适用范围：** 固定机位、人物全身、球杆和球完整入镜的 DTL（正后方）与 Face-on（正面）视频

## 1. 背景与目标

SwingArc 当前已经具备人体姿态取样、P1–P8 候选求解、有限的杆身/球证据和少量技术指标，但这些能力尚未通过多人、逐帧真值数据证明达到可用于挥杆教学的准确度。特别是，现有物体检测只能在少量候选帧提供杆身或球证据，不能连续、准确地跟踪杆头。

本设计把“能够输出结果”升级为“结果经过可复现的准确度验收”，目标为：

1. 准确识别标准 P-System 的 P1–P8 源视频帧；
2. 连续识别手、手臂、头、脊椎、身体和杆头的二维运动轨迹；
3. 输出挥杆分析需要且能从标准二维视频可靠得到的角度、位移、节奏和路径参数；
4. 对遮挡、出画、画质不足和二维视频无法测得的数据明确拒绝或标为估算，不伪造确定结果；
5. 建立可持续加入授权实拍视频、人工修正、重新训练和独立验收的闭环。

## 2. 范围与非目标

### 2.1 第一阶段支持范围

- 固定不移动的手机机位；
- DTL 与 Face-on 两种标准视角，分别配置和验收；
- 人物全身、双手、球杆、杆头和球在关键挥杆区间内完整入镜；
- 原始视频保持真实帧率和时间戳；
- 分析和 Core ML 推理默认在设备本地完成；
- P 位、人物关键点和杆头标注均允许用户或标注人员逐帧移动修正。

任意斜角、移动机位、严重裁切、多人交叉遮挡和非标准镜头不属于第一阶段准确度承诺。质量门可以识别并拒绝这些输入，但不得把拒绝样本计为成功分析。

### 2.2 单目二维视频不能准确提供的数据

第一阶段不把下列数据作为实测结果：

- 真实三维杆头速度（mph 或 km/h）；
- 真实攻角、杆面角和动态杆面倾角；
- 真实三维髋肩旋转、球杆平面和身体深度位移；
- 球速、起飞角、倒旋、侧旋、落点和距离；
- 球杆或肢体被完全遮挡期间的真实空间位置。

对应升级路径为：同步双机位与相机标定用于部分三维重建；120/240 FPS、固定曝光和已知尺度用于改善速度估算；Launch Monitor、雷达或专用传感器用于杆面和球飞行数据。完全遮挡区间只能显示路径缺口，或以明确的虚线和“估算”标签展示预测，预测值不得进入实测准确度统计。

## 3. 已确认验收标准

验收数据必须按球员隔离，不能把同一球员的视频拆到训练集和验收集。最终保留集至少包含 10 位未参与训练和调参的球员，并分别报告 DTL 与 Face-on；样本数量不足的视角不得宣称已达到该视角准确度。

| 能力 | 第一阶段通过标准 |
| --- | --- |
| P1–P8 | 每个视角、每个阶段至少 90% 的自动结果位于双人裁定真值的 ±2 个源视频帧内；未解析和错误确认均计为未通过 |
| 人体关键点 | 可见关键点的中位二维误差不超过人物身高的 3%；同时报告 P90 误差、漏检率和各关键点结果 |
| 杆头轨迹 | 可见帧中至少 90% 成功跟踪，且成功帧的误差不超过画面对角线的 2%；遮挡帧单独统计，不得用预测冒充检测 |
| 失败行为 | 遮挡、出画、机位不合格或置信度不足时明确返回无法识别及原因，不得为了补齐阶段或轨迹而猜测 |

`/Users/liangbo/Desktop/test` 中现有 8 段 MOV 用于建立标注流程、锁定当前算法基线和第一轮调试。它们参与调参后不再具备独立验收资格。

## 4. 标准 P1–P8 契约

本设计沿用标准 P-System，并取代旧文档中把击球当作 P6、把收杆当作 P8 的过时语义：

| 阶段 | 标准位置 | 必需核心证据 |
| --- | --- | --- |
| P1 | 准备位 | 持续起杆前最后一个稳定准备帧；人物、手和球杆处于有效准备状态 |
| P2 | 上杆杆身平行 | 上杆方向成立，杆身最接近水平；缺少可靠杆身证据时不能确认 |
| P3 | 上杆前导臂平行 | 前导臂接近水平并保持伸展，手部持续上升 |
| P4 | 上杆顶点 | 顶点平台末端、持续下杆开始之前的最后一帧 |
| P5 | 下杆前导臂平行 | 前导臂接近水平，手部持续下降并具备下杆身体运动证据 |
| P6 | 下杆杆身平行 | 击球前杆身接近水平；必须有可靠杆身证据，不能借用击球帧 |
| P7 | 击球 | 杆头到达稳定球位或球位发生击球变化，并满足完整时序约束 |
| P8 | 击球后杆身平行 | P7 后杆身再次接近水平；必须有击球后的可靠杆身证据 |

所有自动阶段必须引用真实源视频帧，并满足 `P1 < P2 < … < P8`。状态模型允许单个阶段为 `unresolved`，不得为了输出八个阶段而选择不符合定义的帧。

## 5. 混合识别架构

采用“人体姿态模型 + 高尔夫专用物体模型 + 时序状态模型 + 确定性指标引擎”的混合架构，而不是继续扩大单帧规则或直接训练不可解释的端到端整段视频模型。

```text
原始视频
  → 输入质量与机位检查
  → DTL / Face-on 路由
  → 人体关键点模型 ─────────┐
  → 球、握把、杆身、杆头模型 ├→ 逐帧关联、时序防抖与遮挡状态
                            ┘
  → P1–P8 约束状态求解
  → 二维角度、位移、节奏与路径计算
  → 置信度、无法识别和估算标记
  → 视频叠层、结果报告与人工修正
```

### 5.1 输入质量与视角路由

分析前验证：视频轨可读、帧率和时间戳有效、固定机位、单一主球员、全身覆盖、球杆/球覆盖、亮度和运动模糊可接受。DTL 和 Face-on 使用独立配置、特征权重和准确度报告，不混用一套阈值掩盖视角差异。

### 5.2 人体关键点支路

人体支路输出头部、双肩、双肘、双手腕、双手中心、双髋、双膝和双脚的二维坐标、可见性与置信度，并计算肩线、髋线、脊椎轴和人体尺度。Apple Vision 可以作为基线或降级路径；若其手腕、肘部或高速动作误差不能通过验收，则替换或叠加高尔夫姿态 Core ML 模型，而不是继续用阈值掩盖模型误差。

### 5.3 球杆与球支路

新增高尔夫专用关键点/检测模型，至少输出球、握把、杆身方向和杆头。杆头必须具有独立身份，不能把任意杆身端点默认当作杆头。跨帧关联结合检测置信度、光流或运动模型、杆身几何约束和遮挡状态；检测结果、短时预测和缺失状态必须分开保存。

### 5.4 时序与阶段求解

逐帧特征先经过短窗防抖，再由受约束时序模型寻找 P1–P8。模型同时使用人体、手部、杆身、杆头、球位和运动方向，不允许单个角度阈值决定阶段。P2、P6 和 P8 必须具备各自的杆身平行证据，P7 必须具备杆头/球位与时序证据。

### 5.5 置信度与拒绝机制

每个阶段、关键点、轨迹段和派生参数都保存：数值、时间、置信度、可见性、来源和模型版本。证据不足时返回 `unresolved` 或缺失值；预测轨迹只能标为 `estimated`。下游技术评价不得消费未满足最低证据的参数。

## 6. 数据与输出契约

每个分析帧至少保存：

- 源帧索引和精确时间戳；
- 视角、左右手设置、人物跟踪身份；
- 人体关键点的归一化坐标、置信度和可见性；
- 头部中心、肩线、髋线、脊椎轴和人体尺度；
- 球、握把、杆身两端、杆头的坐标、置信度和检测/预测状态；
- 平滑前与平滑后的轨迹值，避免无法审计处理结果；
- 使用的模型、阈值配置和分析版本。

每个 P 位保存：帧号、时间、阶段状态、总置信度、证据分项、对应人体/球杆快照和人工修正状态。用户锁定的人工修正不得被重新分析覆盖。

## 7. 第一阶段参数清单

### 7.1 连续轨迹

- 头、肩、肘、手腕、双手中心、髋、膝、脚的二维路径；
- 握把、杆身方向和杆头的二维路径；
- 上述点的二维归一化位移、速度和运动方向；
- 检测区间、估算区间和缺失区间。

### 7.2 身体角度与位移

- 脊椎二维倾角与相对 P1 的变化；
- 肩线和髋线的投影角度；
- 双肘角、前导臂伸展和双膝角；
- 头部横移/升降、髋部横移/升降；
- 身体中心和重心代理的二维变化；
- 起身、下沉、侧移和脊椎稳定性趋势。

### 7.3 挥杆结构与球杆参数

- 上杆时间、下杆时间及节奏比；
- 手部路径、杆头路径和二维相对速度；
- 杆身投影角度、二维挥杆平面代理；
- 肩髋分离的二维代理；
- 每个 P 位对应的全部可用角度、位移、轨迹位置和证据状态。

所有带“代理”的数据必须在界面和导出中使用准确名称，不能缩写成真实三维测量值。

## 8. 标注、训练与持续学习

### 8.1 标注流程

每段视频记录视角、惯用手、原始帧率、有效挥杆区间和输入质量。P1–P8 由两名标注者独立逐帧标注；分歧超过 2 个源视频帧时必须由复核者裁定。

人体关键点、球、握把、杆身和杆头先由模型预标注，再由人工在原始帧上移动修正。杆头验收样本必须覆盖所有可见帧，并明确标注遮挡、出画和运动模糊。训练标签不能由未经复核的模型预测直接生成。

### 8.2 数据集隔离

数据按球员而不是按帧或视频随机划分为训练、验证和保留验收集。数据拆分清单在训练开始前锁定并版本化；保留集不得用于阈值调整、模型选择或错误分析后的再训练。若保留集被用于调试，必须重新建立新的隔离验收集。

### 8.3 视频授权与隐私

仅使用获得明确授权的原始视频训练。记录授权范围、是否允许训练、是否允许内部保存和是否允许发布演示。视频、标注和模型训练包默认保存在本地；App 不在后台自动上传或从用户录像中自学习。只有人工确认并明确导出的标签包才可进入训练流水线。

## 9. 失败和降级行为

- 机位、覆盖、画质或媒体不合格：分析前拒绝并给出重新拍摄指引；
- 主球员无法持续锁定：停止阶段确认，保留可回放视频和具体原因；
- 局部人体关键点遮挡：保存可见结果，受影响角度返回缺失；
- 杆头出画或完全遮挡：轨迹断开，预测仅用虚线和“估算”显示；
- 单个 P 位证据不足：显示具体阶段无法确认，其余阶段和轨迹仍可查看；
- 技术参数依赖缺失关键点：不计算该参数，并说明所缺证据；
- 模型升级后结果改变：保留分析版本，可复现旧结果并允许用户选择重新分析。

错误文案必须区分媒体读取失败、输入质量不足、人体检测失败、球杆检测失败、阶段无法确认和参数证据不足。

## 10. 分阶段交付

1. **基准建立：** 标注现有 8 段视频，冻结当前算法，生成逐视频、逐阶段和逐关键点基线报告；
2. **人体轨迹：** 完成人体关键点误差评估、时序防抖和遮挡状态，先达到人体轨迹门槛；
3. **球杆模型：** 建立握把/杆身/杆头/球标注、训练和连续跟踪，未达标前标为实验能力；
4. **P1–P8：** 用完整时序证据重训或重构阶段求解，并分别通过 DTL 与 Face-on 验收；
5. **参数与回放：** 接入已确认的二维参数、轨迹叠层、置信度和人工修正；
6. **独立验收与端侧发布：** 在保留球员数据上验收，转换 Core ML，并测试不同 iPhone 的性能、内存、耗电和结果一致性。

每一阶段必须有机器可读报告和固定回归数据。前一阶段未通过准确度门槛，不得用界面完成度代替算法验收。

## 11. 测试与报告

### 11.1 算法单元与属性测试

- P1–P8 严格递增，缺失证据时保持未解析；
- P2/P6/P8 没有可靠杆身证据时不得确认；
- P7 不得被 P6 或 P8 帧替代；
- 平滑不能改变源帧身份或跨越真实运动转折；
- 检测、估算和缺失状态在保存、重新打开和重新分析后保持；
- 左右手和两个视角使用正确的坐标约定。

### 11.2 数据集评估

报告至少包含：

- 每段视频、每个阶段的人工帧、自动帧、绝对帧误差、状态和置信度；
- 每个视角、每个 P 位的 ±2 帧通过率、未解析率和错误确认率；
- 每个身体关键点的中位误差、P90 误差和漏检率；
- 杆头可见帧跟踪率、误差分布、身份切换和最长连续缺口；
- 输入质量拒绝的准确率及错误拒绝样本；
- 模型版本、数据集版本、设备和运行耗时。

合成数据、规则构造样本和参与调参的视频只用于回归，不能作为真实视频准确度证明。

### 11.3 端侧验收

- 原始 30/60/120/240 FPS 视频的帧号和时间戳映射正确；
- Core ML 与离线基准模型在容差内输出一致；
- 长视频取消、失败和重试不会泄漏任务或覆盖人工修正；
- 不联网时可以完成支持范围内的分析；
- 低内存和设备发热情况下明确降级或停止，不输出部分伪完成结果。

## 12. 完成定义

只有当以下条件全部满足时，才能对外声明第一阶段“准确识别”：

1. DTL 与 Face-on 各自拥有合格且隔离的真实视频验收结果；
2. P1–P8、人体关键点和杆头轨迹均达到第 3 节门槛；
3. 所有未达到或无法从二维视频获得的参数已在产品中明确限制；
4. 人工修正、数据来源、模型版本和估算状态可追溯；
5. Core ML 真机结果与离线评估一致，并通过性能与稳定性检查。

若任一门槛未通过，发布说明必须列出实际通过率、失败场景和下一步数据或模型方案，不得以“AI 分析完成”替代准确度结论。
