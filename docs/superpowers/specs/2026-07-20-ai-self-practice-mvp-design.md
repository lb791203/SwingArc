# SwingArc AI 自助練球 MVP 設計

**日期：** 2026-07-20
**狀態：** 已確認，待實作計畫
**範圍：** iPhone 本機端自助練球、單球分析與既有影片分析工作台整合。

## 1. 產品目標

SwingArc 從專業影片畫線工具延伸為單人可操作的 AI 自助練球 App。球友將 iPhone 架在腳架上後，可在不接觸螢幕的情況下完成連續揮杆、影片裁切、離線分析與語音回饋；走回手機後可查看慢動作、分析證據與對應 Drill。

最高優先順序為：

1. 戴高爾夫手套也能操作。
2. 使用者站在距離手機兩公尺處也能看清狀態、聽到回饋。
3. 所有可讀診斷均有本機影片分析證據；不使用假分數、排名或猜測性結論。

## 2. MVP 範圍

### 2.1 首頁

首頁提供三個同等可見、至少 64 × 64 pt 的入口：

- **正後方練習（DTL）**：進入正後方構圖與診斷規則。
- **正面練習（Face-on）**：進入正面構圖與診斷規則。
- **導入已有揮杆影片**：從相簿選片，直接開啟分析工作台。

正後方與正面是兩種獨立的單機位練習。MVP 不宣稱一部 iPhone 可同時錄製兩個視角；一次練習只能使用一個視角。

### 2.2 現場自動練習流程

```text
首頁選擇視角
  → 相機對齊（對應視角的人形與目標線引導）
  → 使用者手動點選一次「開始自動練習」
  → 連續等待擊球
  → 偵測擊球、裁切本球影片、離線分析
  → 語音播報一項優先調整
  → 短暫顯示大字結果
  → 自動回到等待擊球
```

手動點選開始是已確認的安全門檻：它避免剛架好腳架或正在調整構圖時的誤錄。開始後，使用者不必為每一球回到手機操作。

練習畫面唯一的主操作是：

- 尚未開始：`開始自動練習`
- 已開始：`暫停自動練習`

設定、匯出、分享、歷史與複雜編輯不可出現在遠距待命畫面。

### 2.3 單球回饋

每球處理完成後：

- 優先以語音播報結果。
- 畫面以大字顯示本球主要結果，例如「第 12 球：下杆略偏外」。
- 顯示後自動返回待命，不中斷連續練習。
- 使用者可在任意時候點選「查看上一球慢動作」進入分析工作台。

完整分析頁以一個「本球優先調整」為首要資訊。例如「下杆略偏外」搭配短、可執行的下一球提示及對應 Drill。脊椎、下杆、送杆等各項已確認結果會保留為次要證據；未能可靠判定的項目標記為「未判定」。

### 2.4 既有影片分析與導入

導入影片不進入現場自動偵測循環，而是直接開啟既有分析工作台。工作台繼續支援：

- 慢動作播放與逐格控制。
- P1–P8 自動建議與手動修正。
- 姿態、頭部軌跡、脊椎與參考網格疊層。
- 手動畫線、調整、儲存與分享。

現場自動錄製產生的每一球也使用同一個工作台。因此兩條入口共用影片回看與人工覆核能力。

## 3. 視覺與互動系統

### 3.1 色彩與文字

- 練習模式背景：深石墨 `#0A0F1D`。
- 已就緒／可開始／待命：螢光綠 `#00E676`。
- 注意：黃 `#FFD600`。
- 明確錯誤：紅 `#FF1744`。
- 一般文字以高對比白色或淺灰顯示；色彩不能作為唯一狀態訊號。

練習模式在兩公尺外必須清楚識別的文字僅限：`機位已對齊`、`等待擊球`、本球大字結果與暫停狀態。一般設定或技術數據不得與這些狀態競爭。

### 3.2 手套與戶外規格

- 所有現場核心熱區至少 64 × 64 pt，並保有可見間距。
- 只使用單擊完成核心操作；不依賴長按、雙指縮放、精細拖曳或滑動手勢。
- 構圖框只說明機位與人體是否對齊，不宣稱對動作作出品質判斷。
- 一分鐘未偵測到揮杆時，畫面轉入低亮度待命，僅保留狀態燈與必要文字；重新偵測到使用者回到構圖框後恢復。

### 3.3 分析工作台

分析工作台維持影片優先：

- 黃色表示目前影格與活動 P 點。
- 青色表示可選的 AI 姿態輔助疊層。
- 紅色僅標示實際分析到的問題位置或軌跡區域。
- Drill 是單球優先調整之後的次要行動，不遮擋慢動作與證據。

## 4. 系統邊界與資料流

### 4.1 主要模組

- **Practice Home**：呈現三個入口與最近使用的練習設定。
- **Live Practice Session**：處理視角選擇、相機預覽、對齊、開始／暫停、擊球偵測、短片裁切與連續待命。
- **Swing Analysis**：對儲存的單球影片進行本機姿態與階段分析，輸出帶有信心狀態的結果。
- **Analysis Workspace**：顯示影片、疊層、P1–P8、優先調整、Drill、畫線與媒體動作。
- **Local Project Store**：保存本機影片、分析結果、工作台標註與專案資料。

### 4.2 本機與隱私

MVP 中相機影片、分析結果與專案資料只儲存在 iPhone 本機；不需要帳號、雲端同步、排行榜或伺服器端推論。

### 4.3 結果真實性

分析只可輸出已由影片證據支持的結果。下列狀態必須清楚區分：

- 已確認：有足夠姿態／階段證據，顯示結果與對應疊層。
- 低信心：可呈現候選觀察，但明確說明信心不足，不做強結論。
- 未判定：遮擋、人體未辨識、影片不完整或關鍵階段不足；保留影片，允許人工分析。

不得以固定分數、趨勢數字、全球排名、虛構 P 點或猜測性的建議填補空白資料。

### 4.4 失敗與降級

- 相機不支援預期高速格式時，顯示實際可用幀率並使用受支援格式；不可宣稱固定 240 FPS。
- 麥克風權限缺失或音訊不可用時，顯示具體授權／重試說明；不靜默假裝自動截球成功。
- 溫度、儲存空間或相機錯誤達安全門檻時，停止自動錄製並保留已完成影片。
- 分析失敗時，影片仍可在工作台慢放、畫線、儲存與分享。

### 4.5 分段準確度與持續校準

動作技術評判以前，P1–P8 分段必須先通過真值驗收。現有分段引擎可作為起點，但不可把尚未以實拍資料校準的結果當作技術診斷依據。

- 每支校準影片必須記錄視角（DTL 或正面）、慣用手、原始幀率、時長，以及 P1–P8 的人工真值幀。
- P 點標註至少經過兩次獨立標註；有歧義的階段保留為未確認，不強制選一幀。
- 評估輸出逐 P 點幀誤差、解析率、漏檢率與誤檢率，並依視角、幀率與慣用手分組。
- 自動結果只有在真值集的既定門檻未退步時才可升級；新規則或模型必須和目前基線並列評估。
- 使用者手動修正的 P 點立即覆蓋該影片自動結果，並只在累積足夠同一使用者、同一視角的高信心修正後，調整本機個人校準參數。
- 個人校準只能調整有限的時間偏移、平滑與閾值；不可在裝置上以少量使用者資料重訓通用 Vision 人體模型。
- 若使用者日後明確授權，才可將去識別化的影片衍生特徵、原始結果與人工修正匯出成版本化訓練／評估資料；MVP 預設不匯出資料。

## 5. 不在 MVP 的範圍

以下功能移至下一階段：

- 揮杆日記、日曆與錯誤率趨勢。
- 綜合評分、排名、社群與訂閱成長機制。
- 帳號、雲端同步與伺服器端 AI。
- 多機位同步錄製。

## 6. 驗收標準

最終驗收必須在真實 iPhone 和練習場場景完成，不能只以編譯成功或模擬器畫面替代。

1. 戴手套可在不誤觸的情況下，完成選擇視角、對齊及一次手動開始。
2. 使用者位於兩公尺外，可辨識機位已對齊、等待擊球、正在處理、本球結果與暫停狀態。
3. DTL 與正面各完成連續多球的自動待命循環；每球回饋後無需手動重新開始。
4. 每一個播報結果均可在分析工作台追溯至影片、P 點或姿態／軌跡證據。
5. 人體未辨識、低信心、音訊權限缺失、過熱及空間不足均顯示明確可行的處理方式。
6. 導入影片持續支援慢放、逐格、P1–P8、畫線、專案保存與匯出／分享。
