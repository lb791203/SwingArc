# SwingArc 自动挥杆教练设计

日期：2026-07-21  
状态：已确认设计，待用户审阅规格后进入执行计划。

## 目标

把 SwingArc 从“用户手动开始分析的视频工具”升级为本地自动挥杆教练：每次导入视频或完成自动截取的一球后，App 自动分析、仅展示有证据的轨迹和判定，并在练习场用简短语音给出最高优先级纠错建议。

所有视频、姿态、指标、语音决策和练习历史都保留在设备本地；不使用云端推理。球杆类别识别不属于本阶段。

## 用户流程

### 导入视频

1. 用户导入视频后直接进入视频优先的检看页；没有“开始 AI 分析”主按钮。
2. 系统后台自动检测连续视频中的每次完整挥杆，生成按时间排序的 `SwingAttempt`。
3. 每个 `SwingAttempt` 独立执行：主球员锁定、P1–P8 分段、人体和杆身证据采样、指标计算和置信度判定。
4. 回放默认不叠加任何技术线。用户从中央参数胶囊选择一项或多项指标后，才叠加对应轨迹、角度或辅助线。
5. 不足以分析的一球保留视频并显示具体原因；不产生阶段、轨迹、分数或纠错结论。

### 自动练习拍摄

1. 击球声触发后保存单球短片并立即进入同一分析队列。
2. 分析完成后，只在存在高置信度结果时播报一条最高优先级反馈。
3. 无明确问题且证据充分时播报简短肯定；证据不足时只提示重新调整机位或全身入镜。
4. 若存在高置信度问题，显示对应 Drill；语音不堆叠多项问题。

## 分析管线

```text
媒体导入 / 自动截取
  → 连续视频逐球分段
  → 主球员身份锁定
  → P1–P8 时序分段
  → 姿态、手部、杆身与球位证据
  → DTL / 正面指标量测
  → 目标带、个人基线、置信度判定
  → 回放叠层 / Drill / 语音反馈
```

### 逐球分段

- 优先用击球声、手部速度峰值、杆身运动和球位局部变化定位候选击球区域。
- 每个候选区域必须能形成时序合理的准备、上杆、下杆、击球、送杆窗口；不能形成完整窗口则保留为未分析片段。
- 长视频允许有多球；每球独立保存，不能把相邻两球拼成一个结果。

### 主球员与 P 点

- 主球员身份由画面位置、身体尺度、跨帧连续性与稳定球位共同约束。
- 若同一身份无法跨帧稳定，立即停止该球的技术分析并说明原因。
- 自动 P 点只接受有足够姿态与时序证据的结果。人工 P 点是锁定点位，能用于当前球回放与后续训练资料，但不自动成为全局标准真值。

## 指标与证据门槛

| 视角 | 指标 | 最低证据 | 首阶段状态 |
| --- | --- | --- | --- |
| DTL | 髋部前倾、髋部深度、膝屈、手位、脊柱稳定、头部位置 | 清晰人体姿态 + 固定机位 | 优先开放 |
| DTL | 手部路径 | 双腕／双手多帧轨迹 | 优先开放 |
| DTL | 挥杆平面 | 杆身连续证据 + DTL 校准 | 第二阶段开放 |
| 正面 | 髋位、胸位、手位、站距、脊柱侧倾、前导肩、前导髋、头部位置 | 清晰人体姿态 + 正面校准 | 优先开放 |
| 正面 | 释放 | 杆身、双手、击球附近证据 | 第二阶段开放 |

每项输出均为 `目标区 / 需关注 / 证据不足`，而不是无条件的“正确 / 错误”。`目标区` 必须同时满足量测可信度、机位可信度和指标目标带；`证据不足` 不显示技术轨迹。

## 标准库与个体化

### 标准库

每个指标保存以下版本化信息：

- 适用机位（DTL 或正面）与挥杆阶段。
- 身体尺度归一化方式，例如肩宽、髋宽、躯干长度或准备位基线。
- 目标带、需关注带、最小样本证据和最低置信度。
- 教练标注版本、验证样本和生效日期。

标准库来自固定录制规范下的教练标注素材。每杆由至少两名专业教练给出“目标区 / 需关注 / 明确问题”和问题类型；有分歧的样本进入复核，不直接用于阈值校准。初版规则只作为保守起点，后续以留出的教练标注集校准误报率与漏报率。

### 个人基线

用户在同一机位完成足够多次高置信度挥杆后，App 建立本人的稳定区间。个人基线只用于趋势和细微偏差提示，不覆盖公共安全边界，也不会把个人数据上传或用于未审核的全局自学习。

## 回放与语音界面

- 普通检看与全屏回放都以视频为中心：没有常驻时间文字、P1–P8 文本或传统播放控制；点击视频播放／暂停。
- 全屏回放只显示有证据的挥杆剪影。已确认点位正常显示，低置信度点位弱化，缺失点位省略。
- 中央参数胶囊进入独立的 DTL / 正面参数页。可选择一项或多项已满足证据条件的叠层；设置页不显示半屏视频。
- 练习语音由单独的 `SpeechCoach` 输出，使用短句：肯定、一个问题、一个 Drill 或拍摄建议。语音前必须通过同一份 `MetricResult` 置信度门槛。

## 数据模型边界

- `SwingAttempt`：单次挥杆的时间范围、机位、分段结果、分析状态、失败原因。
- `MetricMeasurement`：原始归一化量测值、阶段、对应姿态／杆身证据、置信度。
- `MetricResult`：指标、目标状态、偏差方向、证据说明、关联回放叠层与 Drill。
- `SwingStandard`：版本化目标带和适用条件。
- `PersonalBaseline`：仅本机保存的稳定样本统计。

`VideoPlaybackManager` 继续作为唯一播放器所有者；分段、姿态、指标、标准与语音分别为独立服务，避免 UI 直接推导技术结论。

## 实施顺序

1. 稳定主球员锁定、P1–P8 分段和失败原因；先解决当前真实视频中“无法持续锁定主球员”的问题。
2. 增加连续视频逐球分段与 `SwingAttempt` 持久化，并在导入／拍摄后自动排队分析。
3. 实现优先人体指标的 `MetricMeasurement` 与保守的 `MetricResult`，同时让 DTL / 正面参数选择真正控制回放叠层。
4. 接入练习拍摄后的 `SpeechCoach` 与 Drill 决策。
5. 加入杆身证据强化后，再开放挥杆平面与释放。
6. 建立教练标注标准库、验证集和个人基线；逐版本收紧或放宽目标带。

## 验收标准

- 导入与自动截取的一球都会自动开始本地分析；用户不需点击“开始 AI 分析”。
- 连续练习视频中，每个通过时序校验的挥杆均作为独立回放项目。
- 无法锁定主球员、分段不完整或证据不足时，界面只显示原因，不显示技术判断。
- DTL 与正面只显示各自适用的指标；未满足杆身／击球证据时，挥杆平面和释放不可用。
- 已选叠层仅使用对应指标的真实量测结果。
- 自动练习每球最多播报一条经过置信度门槛的语音反馈。
- 所有分析、标准版本和个人基线在本机可追溯；没有云端上传。
