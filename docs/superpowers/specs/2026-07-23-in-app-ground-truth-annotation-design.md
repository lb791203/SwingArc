# SwingArc App 内正式真值标注设计

**日期：** 2026-07-23

**状态：** 已确认架构，待实施计划

**适用范围：** iPhone 与 iPad 本地标注；原始 30/60/120/240 FPS、
固定机位、单人 DTL 或 Face-on 挥杆视频

## 1. 目标

在 SwingArc 内新增独立的全屏标注模式，把 Apple Vision 和现有挥杆
分析结果作为预标注，再由人工逐帧修正并锁定：

- 标准 P-System 的 P1–P8 源视频帧；
- 人体关键点；
- 握把、杆身两端、杆头与球；
- 关键点的可见、遮挡、出画和无法确认状态；
- 两名标注者的独立结果与分歧裁定。

标注结果形成可审计、可导出、可用于离线训练和独立验收的标准数据包。
原片保持只读，标注模式不改变普通分析项目、手动画线或用户媒体。

## 2. 项目分解

剩余算法工作分为三个依赖顺序明确的子项目：

1. **App 内正式标注模式：** 本设计范围。
2. **高尔夫物体模型与连续跟踪：** 使用已授权、已复核的关键点标签训练，
   输出握把、杆身、杆头和球。
3. **P1–P8 融合求解：** Apple Vision 提供人体主干，球杆模型提供
   P2/P6/P7/P8 核心证据，人工真值负责调试与验收。

第 1 项通过验收前，不开始正式模型训练。未经人工复核的 AI 预测不得进入
训练集。

## 3. 入口与模式隔离

分析工作台工具区增加“标注”入口。进入后以全屏页面显示
`AnnotationWorkspaceView`，普通分析工作台暂停播放但保留原状态。

标注数据保存到独立的 `SwingArcAnnotations` 目录，以原片内容指纹作为身份，
不写入 `LocalAnalysisProject`。退出标注模式后，普通项目的 P 点、图形、
分析结果和媒体状态保持不变。

正式标注模式分为五步：

1. 任务资料；
2. P1–P8 独立标注；
3. 人体与球杆关键点标注；
4. 双人结果比较与分歧裁定；
5. 冻结、验证和导出。

## 4. 原片与精确帧身份

标注必须复用分析器的真实源帧时间线。对于可变帧率 iPhone 原片，
`sourceFrameIndex / averageFrameRate` 不是合法取帧方式。

新增共享的精确帧服务：

- 通过解码样本的 presentation timestamp 建立有序源帧时间线；
- 按源帧序号前进或后退一帧；
- 所有标注保存真实源帧序号和精确时间戳；
- 画面方向使用视频轨旋转信息统一为用户看到的方向；
- 帧提取结果必须与保存的源帧序号双向校验；
- 原片指纹、帧数、时间线指纹任一变化时，禁止把旧标签套用到新文件。

标注播放器提供前后 1 帧、前后 5 帧、播放/暂停、速度切换、双指缩放和
局部放大镜。界面同时显示当前源帧号、总帧数和精确时间。

## 5. P1–P8 标注契约

标注使用 `p-system-v1`，语义固定为：

| 阶段 | 标准位置 |
| --- | --- |
| P1 | 持续起杆前最后一个稳定准备帧 |
| P2 | 上杆杆身最接近水平的真实帧 |
| P3 | 上杆前导臂最接近水平的真实帧 |
| P4 | 顶点平台末端、持续下杆前最后一帧 |
| P5 | 下杆前导臂最接近水平的真实帧 |
| P6 | 击球前下杆杆身最接近水平的真实帧 |
| P7 | 杆头到达稳定球位的击球帧 |
| P8 | P7 后杆身再次最接近水平的真实帧 |

必须满足 `P1 < P2 < … < P8`。无法确定的阶段保存为 `unresolved`，
不允许用相邻阶段或固定时间补齐。

Apple Vision 与当前分析器只生成预标注：

- P1/P3/P4/P5 主要显示人体和运动方向证据；
- P2/P6/P8 显示候选区间，但缺少杆身证据时不得预先标为已确认；
- P7 缺少杆头/球位证据时不得预先标为已确认。

人工选择源帧后保存为手动锁定结果。重新分析可以更新预标注，但不得覆盖
任何人工锁定帧。

## 6. 双人独立标注与裁定

每个任务至少包含 `annotator-a` 和 `annotator-b` 两个标注会话。
开始会话时选择本机标注者身份；同一标注者不能创建两个有效独立通道。

独立性规则：

- 标注者 B 完成并提交前，不显示标注者 A 的帧号和点位；
- 已提交会话只读，修改必须创建带时间戳的新修订；
- 两次 P 点相差不超过 2 个源帧时，系统显示建议中间帧，但仍记录两个原值；
- 相差超过 2 帧或任一方为 `unresolved` 时，进入裁定队列；
- 裁定者逐帧选择唯一标准帧或确认 `unresolved`；
- 裁定结果保留裁定者、时间、两次原始选择和说明。

关键点标签必须经过复核者确认才能标记 `reviewed: true`。

## 7. 关键点与可见性

人体关键点：

- 头部中心；
- 左右肩、肘、手腕；
- 双手中心；
- 左右髋、膝、脚踝。

高尔夫关键点：

- `grip`：双手握杆中心；
- `shaftStart`：靠近双手一侧的杆身中心线；
- `shaftEnd`：杆身靠近杆颈处的中心点；
- `clubhead`：杆头可见区域中心；
- `ball`：球中心。

坐标保存为经过方向修正后画面的左上角原点归一化坐标。每个点必须保存
以下状态之一：

- `visible`；
- `occluded`；
- `out-of-frame`；
- `unresolved`。

只有 `visible` 点参与坐标训练损失与可见帧准确度统计。预测点以虚线显示，
来源为 `predicted`；人工移动或确认后来源变为 `manual`。遮挡期间的预测
不能被人工确认按钮批量转换为真实检测。

## 8. 标注帧队列

第一版不要求人工标注原片每一帧。系统生成可审计的建议队列：

- P1–P8 标准帧全部进入；
- P1–P5 区间默认每 4 个源帧进入一个建议帧；
- P5–P8 高速区间默认每 2 个源帧进入一个建议帧；
- 杆头明显模糊、遮挡、出画和错误预检测帧必须保留；
- 标注者可添加任意源帧，但不能删除已被另一标注会话或裁定引用的帧。

队列规则和版本写入导出数据包，以便模型训练能够复现采样来源。

## 9. 本地数据与导出

每个标注包至少保存：

- schema 版本和 P-System 版本；
- 原片文件名、内容指纹、帧时间线指纹、尺寸、方向和精确帧数；
- 匿名 `golferID`、DTL/Face-on、左右手；
- 授权状态和数据集用途；
- 标注者会话、修订和提交状态；
- P1–P8 原始选择与裁定结果；
- 逐帧人体与高尔夫关键点；
- 可见性、来源、复核者和复核状态；
- AI 模型版本与分析版本；
- 导出时间和数据包校验值。

默认导出 JSON 标注包，不包含原始视频字节。视频只保存在本地 App 容器或
用户主动选择的位置。只有授权状态为 `training-allowed`、双人阶段标注完成、
关键点已复核的数据可以标记为训练或验证数据。

同一球员的训练、验证和保留验收归属由数据清单控制，不能在 App 中把同一
球员分散到多个集合。

## 10. 错误与恢复

- 视频缺失或指纹不一致：停止标注并保留标签，不自动绑定新文件；
- 精确帧读取失败：显示具体源帧号，允许重试，不跳到邻近帧保存；
- P 点顺序错误：阻止提交并突出冲突阶段；
- 元数据或授权未完成：允许保存草稿，禁止冻结为训练数据；
- 标注者身份重复：阻止提交第二个独立通道；
- 关键点未复核：允许内部开发导出，禁止训练导出；
- App 退出或内存压力：每次确认后原子保存，重新打开恢复当前任务和帧；
- AI 重新分析失败：人工标签仍可查看、编辑和导出。

## 11. 测试策略

### 11.1 纯逻辑测试

- P1–P8 严格顺序与 `unresolved`；
- 双人差异不超过 2 帧和超过 2 帧的裁定规则；
- 标注者隔离、提交后只读和修订历史；
- 可见性状态、人工锁定和预测来源；
- 授权与训练导出门；
- JSON 编解码和旧版本迁移。

### 11.2 媒体测试

- 固定帧率与可变帧率视频的源帧序号/时间戳一致；
- 30/60/120/240 FPS 原片前后逐帧无重复、跳帧或邻帧替代；
- 旋转视频的显示坐标与导出坐标一致；
- 文件指纹或时间线变化时拒绝复用标签。

### 11.3 UI 与真机测试

- iPhone 竖屏不依赖横向滚动完成核心标注；
- iPad 使用更大画面但保存同一数据格式；
- 双指缩放、放大镜和点位拖动不会触发视频播放；
- 进入/退出标注模式不改变普通项目；
- 后台切换、强制退出和重新启动后恢复；
- 导出包在 Mac 验证工具中通过格式、授权和双人标注检查。

## 12. 第一版完成标准

第一版必须在 App 内完成以下闭环：

1. 导入一段可变帧率 240 FPS 原片；
2. 精确显示并逐帧访问所有可解码源帧；
3. 两个独立标注者完成 P1–P8；
4. 完成至少一组人体和五个高尔夫关键点标注；
5. 自动生成并完成一项分歧裁定；
6. 冻结人工结果；
7. 导出不含原片的标准 JSON 包；
8. Mac 验证工具确认帧身份、顺序、复核状态和授权规则全部通过；
9. 普通分析项目、绘图和媒体在整个流程后保持不变。

完成该闭环后，进入高尔夫物体模型与连续跟踪子项目。
